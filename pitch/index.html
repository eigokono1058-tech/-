LAST METERS

AIが発注する時代、
ボトルネックは「受取」になる。

AIエージェントが在庫を見て、判断して、発注・決済まで済ませる。 それでも荷物は物理的に人のところへ運ばれる。 いまの物流は「本人が家にいる」前提で設計されているので、自動化はここで詰まる。 この最後の数メートルを、人の在宅からシステムの権限管理に置き換える。

動くデモを触る 事業計画を読む

1. 課題は「まだ残っている受取」

再配達率は11%台から8.3%まで下がった。改善している。だが下がった分の多くは置き配に逃がしただけで、置き配できない荷物がそのまま残っている。

残っている問題は「再配達をゼロにする」ことではない。
置き配に逃がせない荷物（冷蔵・冷凍・医薬品・高額品）を、人が家にいなくても安全に渡すことである。 そしてAIが自動発注するのは、まさにその定期消費財だ。

2. 自動化は「到着」までしか進まない

配送員をロボットやドローンに置き換えても、最後に「誰が受け取るのか」が残る。ラストワンマイルの先の、ラスト数メートル。

人間型ロボットが家で代わりに受け取る、という解もある。だがそれは玄関の解錠権限をロボットに渡すことを意味する。 ロボットを制圧・偽装できれば住居侵入がそのまま成立してしまう。 だからこのプロジェクトは逆を選ぶ —— 「家で受け取らなければならない」という前提そのものを消す。

3. 解くのは「箱」ではなく「権限」

ロッカーやロボットを増やす競争ではなく、その手前の制御層を取る。既存のコンビニ・駅ロッカー・宅配BOXは、新しく作らなくてもそのままノードになる。

① RECEIPT GRANT

物理世界のアクセストークン

誰に・どこで・いつまで・何を許すかを、最小スコープ・時限付き・失効可能な形で発行する。AIエージェントにTool権限を渡すのと同じ発想。渡していない権限を明示できるのが要点。

② RECEIVING GRAPH

受取地点を能力で抽象化

温度帯・本人確認・施錠・空き枠・動的（人や車両）という能力でモデル化し、コンビニも駅ロッカーも勤務先も移動中の本人も同じインターフェースで扱う。

③ HANDOFF PROTOCOL

占有移転の証跡

「置いた／受け取った」ではなく、機体認証→グラント照合→認証→温度証跡→スコープ内解錠→占有移転を、署名付きイベントとして残す。これが責任分界の土台になる。

受取先を、住所ではなく「地点と人」にする

タクシーに乗るついでに受け取る。コンビニで受け取る。勤務先で受け取る。暗証番号を一時的に共有して友人に委任する。 移動中の自分（GPS）に届けてもらう。 シェア自転車の返却場所をピンで指すように、受取地点を指定する。 個別の機能は既にある。足りないのは配送中にこれらを安全に・即時に切り替える層だけだ。

4. 全部自動化しないことを設計する

AIエージェントのガードレール設計とまったく同じ構造。リスクに応じて人間の介入点を決める。

L0手動受取方法の決定も受渡しも人間。いまの宅配
L1提案のみAIが提案し、実行は毎回人間が承認
L2低リスク自動常温・低額のみ自動実行
L3例外時のみ人間 ／ 既定値正常系は自律実行。認証失敗・温度逸脱・破損だけ人間へエスカレーション
L4屋内まで委譲 ／ 採らない玄関解錠と屋内搬入まで渡すと、乗っ取りリスクを人間が肩代わりできない

価値が出るのは正常系ではなく例外時の処理速度。設計原則は4つ: ①権限は時間で切れる（通信が切れたら開かないのが正しい） ②認証失敗はリトライで突破させない ③ロボットを制圧しても中身と住居権限は取れない ④例外の大半は「時間切れ」なので期限設計が運用コストを決める。

5. 困っている人と、払う人は違う

「困っている人」「使う人」「設備を入れる人」「金を払う人」は同じではない。ここを間違えると、良い仕組みを作っても売れない。

立場ペイン経済インパクト課金
生活者不在で受け取れない／冷蔵冷凍の時間制約／置き配の盗難不安時間と手間（金額化しにくい）無料
配送事業者再配達の人的負荷／ドライバー不足／小口化直接コスト成功報酬（一次）
マンション・不動産宅配BOX不足／建物内アクセス管理／住民向け差別化設備投資と資産価値SaaS（二次）
EC・小売配送コスト／配送品質がCVRに影響売上への間接影響API従量（三次）

だから最初の課金者は生活者ではない。生活者は「支払者」ではなく「受取成功率を上げる参加者」として無料で参加してもらう。

Phaseやること設備投資検証する仮説
0既存のコンビニ・駅ロッカー・宅配BOXを束ね、配送中の受取先変更を可能にするゼロ動的に変えるだけで再配達は減るか
1動的ランデブー（移動中の本人・委任先への配送）ゼロ〜小「人に届ける」需要は実在するか
2配送ロボットとのM2M受渡し（グラントによる庫室解錠）中機械同士の受渡しはコストを下げるか
3屋内搬入大やらない（権限リスクが利得を上回る）

個人が「荷物を自動で受け取るため」に設備投資をすることはほぼ無い。だから設備投資ゼロのPhase 0から始める。 ここで収益が立たないなら、Phase 2以降に進む意味はない。

6. なぜ今か

労働供給の崖2030年度に輸送能力が約34%不足する試算。再配達削減が「コスト削減」から「事業継続」の問題になった
置き配の標準化置き配が制度として前提化し、その副作用（盗難・プライバシー）が顕在化した
法制度2023年4月の改正道路交通法で自動配送ロボットが「遠隔操作型小型車」として届出制で公道走行可能に（長さ120cm×幅70cm×高さ120cm以下・最高速度6km/h）。2025年2月には経産省WGがより配送能力の高いロボットの社会実装を検討
AIエージェント発注・決済までAIが実行する設計が現実的になり、受取が相対的にボトルネックになった
世帯構造単独世帯は34.6%（2024年）、2050年に44.3%の見込み。「家に人がいない」が標準になる

出典：国土交通省、経済産業省（自動配送ロボットの社会実装検討WG, 2025年2月）、厚生労働省 国民生活基礎調査（2024年）、 国立社会保障・人口問題研究所 世帯数将来推計（2024年推計）。

AI時代に重要なのは、既存プロセスの一部をAIに置換することではなく、 AIが自律的に動く前提でプロセス自体を再設計すること。
IT運用で起きている「認識 → 推論 → Action → ガードレール → 監督」の設計が、 物流では「認識 → 判断 → 発注 → 移動 → アクセス → 受渡 → 保管」として現れる。 どちらも、誰が実行し・どこまで自律化し・誰が監督し・誰が責任を持つかの設計問題だ。

8. まだ検証できていないこと

この構想の弱点を先に出す。ここが埋まらないと事業は成立しない。

P0再配達1件の実コストが分からない。成功報酬の単価が決まらない。いま使っている「300円」は仮定にすぎない。
→ 配送事業者に「社内では何円で計算していますか」を直接聞く
P0受取先を動的に変えると再配達が何%減るのか分からない。効果がなければ払う理由がない。
→ 既存の「受取場所変更」機能の利用率データを取る
P0削減効果の測り方に合意できるか分からない。測れない改善には誰も払わない。
P1「移動中の自分に届く」が魅力か気持ち悪いか分からない。位置共有の拒否感が強ければ、目玉機能が折れる。
→ デモの検証タブで実測中
P1法務が未整理。医薬品の受取代替（薬機法）、位置情報の第三者提供（個情法）、受取委任の法的性質、AI自動発注の責任。
P1キャリアが横断プラットフォームに乗るか分からない。自社アプリでの囲い込みと利益相反する。

撤退条件も決めてある: 45日以内に「再配達1件のコスト」の実数が誰からも出てこなければ、課金根拠が存在しないということなので前提を組み替える。 詳細は 足りないもの一覧 と 検証計画 に分けて書いた。
