**この事業計画で一番自信がない点（先に書く）**: 個人が「受取の面倒」に金を払う可能性は低い。
したがって事業として成立するかは **配送事業者の再配達コストを実際に下げられるか** に全部かかっている。
そこが崩れたら、この事業は成立しない。90日でそこだけを検証する。

## 1. 前提認識 — AIエージェントが発注する時代に何が起きるか

いま起きつつあるのは、AIが人間に代わって「判断」し「アクション」まで実行する流れである。
家庭内で言えば、こうなる。

```
冷蔵庫・パントリーが在庫を把握
  → AIが不足を判断
  → 商品を選定
  → 自動で発注・決済        ← ここまでは近い将来かなり自動化できる
  → 物理的に家まで運ばれる
  → ???                     ← 誰が受け取るのか
  → 家庭内で保管
```

人間はバーチャルな存在ではない。何万年と続く肉体の構造は変わらないので、食料も水も薬も**物として**必要になる。
つまり **デジタル上の判断・発注が自動化されるほど、物理世界との接点である「配送と受取」の通過量が増える**。

発注のハードルが下がれば注文頻度は上がる。1回の注文単価は下がり、小口配送が増える。
現在の受取方式（＝本人が家にいることを前提にした対面受取）を維持したままだと、
自動化の利得がそのまま物流側の負荷として跳ね返る。

### 1.1 いま「配送」に対して起きている解決策は、受取を解いていない

配送員をロボットやドローンに置き換えても、自動化は完結しない。

```
AI発注 → 自動倉庫 → ドローン/配送ロボット → マンション到着 → ？？？ → 冷蔵庫へ
```

「ラストワンマイル」の先に、**建物へのアクセス・受渡し・屋内搬入という「ラスト数メートル」**が残る。
ここは技術の問題ではなく、**権限と責任の問題**である。

## 2. 課題 — 数字で見る「受取」のボトルネック

この問題はAI普及後に初めて起きるものではなく、すでに発生している。

| 指標 | 数値 | 出典・年次 |
|---|---|---|
| 宅配便取扱個数 | 約 **50億個/年** | 国土交通省（2023年度・2024年度いずれも約50億個） |
| 再配達率 | **8.3%**（2025年10月）／8.4%（2025年4月） | 国土交通省 サンプル調査（年2回） |
| 再配達率の改善幅 | 2022年10月比 **▲2.2ポイント** | 同上 |
| 再配達に費やされる時間 | 年間約 **1.8億時間** ≒ ドライバー **約9万人分** の労働時間 | 国土交通省試算（2015年／平成27年） |
| 再配達由来のCO2 | 年間 **25.4万トン** | 国土交通省試算（2020年度／令和2年度） |
| 2030年度の輸送能力不足 | **約34%**（約9億トン相当） | 国土交通省「持続可能な物流の実現に向けた検討会」試算 |
| 分譲マンションストック | 約 **713万戸**（2024年末） | 国土交通省 |
| うち築40年以上 | 約 **148万戸**（全体の約2割） | 同上 |
| 単独世帯 | **1,899万世帯・34.6%**（2024年） | 厚生労働省 国民生活基礎調査 |
| 単独世帯（2050年見込み） | **44.3%** | 国立社会保障・人口問題研究所 推計 |
| 宅配ロッカー PUDO | 全国約 **6,000カ所**（2025年3月時点） | Packcity Japan 公表 |

### 2.1 数字の読み方 — 「再配達率8.3%」は成功か

再配達率は着実に下がっている（11%台 → 8.3%）。置き配の標準化が効いている。
だがこれは **「置き配に逃がした」結果** であり、受取の問題が解けたわけではない。

- 50億個 × 8.3% ≒ **年間4億個**が、いまも再配達されている
- 再配達1件の直接コストを仮に **300円** とすると、年間 **1,200億円** 規模の無駄 `[要検証]`
  - 仮定: ドライバー人件費＋車両コスト ≒ 3,000円/時、再配達は1時間あたり10件程度
- 置き配に逃がした分は、**盗難・破損・プライバシーのリスクを生活者に転嫁**している
- 冷蔵・冷凍品は置き配できないため、**この改善カーブの外側に残っている**

> つまり残っている問題は「再配達をゼロにする」ことではなく、
> **置き配に逃がせない荷物（冷蔵・冷凍・医薬品・高額品）を、人が家にいなくても安全に渡す**ことである。
> そしてAIによる自動発注が増えるのは、まさに**生鮮・日用品・医薬品という定期消費財**である。

### 2.2 ステークホルダー別のペイン

| 立場 | ペイン | 経済的インパクト | 意思決定者 |
|---|---|---|---|
| 生活者 | 日中不在で受け取れない／冷蔵冷凍の時間制約／再配達調整が面倒／置き配の盗難不安 | 主に**時間と手間**（金額化しにくい） | 本人 |
| 配送事業者 | 再配達の人的負荷／ドライバー不足／小口化／配送効率低下 | **直接コスト**（年1,200億円規模の一部）`[要検証]` | 支店〜本社の物流企画 |
| EC・小売 | 配送コスト／配送品質がCVRと解約率に影響 | 売上・粗利への間接影響 | EC事業責任者 |
| マンション・不動産 | 宅配BOX不足／配送員の建物内アクセス管理／住民向け差別化 | 設備投資と資産価値 | 管理会社・デベロッパー・管理組合 |
| 設備事業者（ロッカー） | 稼働率／設置場所の確保 | 設備の回収期間 | 事業責任者 |

**重要**: 「困っている人」「サービスを使う人」「設備を入れる人」「金を払う人」は同じではない。
生活者の「面倒」より、配送事業者の「再配達コスト」の方が経済的ペインとして大きい。
**だから最初の課金者は生活者ではない。**

## 3. 仮説 — 解くべきは「配送」ではなく「受取の権限」

### 3.1 中心仮説

> 受取が成立しない原因は、物理設備の不足ではなく、
> **「誰が・どこで・いつ・何を受け取っていいか」を動的に決める仕組みがないこと**である。

いまの宅配は、注文時点で「住所」という静的な文字列に受取先が固定される。
だから人が動くと成立しない。逆に言えば、**受取先を「住所」から「権限つきの地点・人」に変えれば、
既存の設備のままでも受取成功率は上げられる**。

### 3.2 具体的に実現する状態

- タクシーやバスに乗るついでに受け取る
- 街中のコンビニ・駅ロッカーで受け取る
- 勤務先で受け取る
- 暗証番号を一時的に共有して、友人や家族に受取を委任する
- **移動中の自分（GPS）に届けてもらう** — 住所ではなく「人」に届く
- シェア自転車の返却場所をピンで指すように、受取地点を指定する

これらは個別には既に存在する（コンビニ受取、ロッカー受取、置き配指定）。
足りないのは、**配送中にこれらを安全に・即時に・自動で切り替える層**である。

### 3.3 「家で受け取る」という概念を消す

人間型ロボット（オプティマスのようなもの）が家で代わりに受け取る、という解もある。
しかしこれは **オートロックや玄関の解錠権限をロボットに渡す**ことを意味する。
ロボットを物理的に制圧・偽装できれば、そのまま住居侵入が成立してしまう。

> したがって本プロジェクトは、**屋内アクセス権を渡さない**方針を採る。
> 「家で受け取らなければならない」という前提自体を消す方向に賭ける。

これは製品上の制約ではなく、**設計方針として明示的に選ぶ**（デモの自律レベルL4を既定で無効にしているのはこのため）。

## 4. 製品 — 受取オーケストレーション・レイヤー

「箱」（ロッカー・ロボット）ではなく、その手前の**制御層**を取る。

### 4.1 3つの構成要素

#### ① Receipt Grant（受取グラント）— 物理世界のアクセストークン

AIエージェントにTool権限を渡すのと同じ発想で、物理的な受取権限を最小スコープ・時限付きで発行する。

```json
{
  "grant_id": "rdg_8f21c7",
  "grantee": { "type": "delivery_robot", "id": "wm-tky-0473",
               "attestation": "mTLS + device_cert(verified)" },
  "order":   { "id": "ord_0031", "temp_class": "frozen", "value_jpy": 4280 },
  "place":   { "type": "locker", "id": "hub_station_04", "radius_m": 8 },
  "window":  { "from": "18:10", "to": "18:40" },
  "conditions": ["one_time_code", "temp_chain>=-18C", "photo_evidence"],
  "scope":   ["open:bay_A3"],
  "not_granted": ["unlock:entrance", "read:order_history",
                  "locate:subject_after_handover"],
  "revocable": true
}
```

要点は `not_granted` を明示すること。**渡していない権限を書けることが、この層の価値**である。

#### ② Receiving Graph（受取地点のグラフ）

受取地点を「能力（capability）」で抽象化して持つ。

- 温度帯: 常温 / 冷蔵 / 冷凍
- 認証: 本人確認可 / 署名可 / 暗証番号のみ
- 保全: 施錠 / 人が常駐 / 屋内
- 動的: 位置が動く（＝人・車両）
- 容量: 空き枠のリアルタイム在庫

コンビニ、駅ロッカー、マンションの宅配BOX、勤務先、友人宅、移動中の本人を**同じインターフェースで扱う**。
新しい設備を作らなくても、既存の設備がそのままノードになる。

#### ③ Handoff Protocol（受渡しプロトコルと証跡）

受渡しを「置いた／受け取った」ではなく、**占有移転イベント**として記録する。

```
DEVICE_AUTH → GRANT_CHECK → (IDENTITY / OTP) → TEMP_EVIDENCE
→ UNLOCK(scope内のみ) → CUSTODY_TRANSFER → GRANT_EXPIRED
```

各イベントに署名を付けて残す。これが後述の責任分界と保険の土台になる。

### 4.2 なぜソフトウェアから始めるのか

既存住宅にロボット用の受取ポートや3温度帯ロッカーを設置するには、相応の初期投資が必要になる。
**「荷物を自動で受け取るために個人がそこまで投資するか」** の答えはほぼ「しない」。

だから順番を逆にする。

| Phase | やること | 必要な設備投資 | 検証する仮説 |
|---|---|---|---|
| **0** | 既存のコンビニ・駅ロッカー・宅配BOXを束ね、配送中の受取先変更を可能にする | **ゼロ**（既存設備のAPI連携） | 受取先を動的に変えられるだけで再配達は減るか |
| **1** | 動的ランデブー（移動中の本人・委任先への配送） | ゼロ〜小 | 「人に届ける」需要は本当にあるか |
| **2** | 配送ロボット・自動配送車とのM2M受渡し（グラントによる庫室解錠） | 中（設備側の対応） | 機械同士の受渡しがコストを下げるか |
| **3** | 屋内搬入 | 大 | **やらない**（権限リスクが利得を上回る） |

Phase 0 で収益が立たないなら、Phase 2 以降に進む意味はない。

## 5. ビジネスモデル — 誰が、何に対して払うのか

### 5.1 課金モデル（3案）

| 案 | 課金先 | 課金根拠 | 単価イメージ | 評価 |
|---|---|---|---|---|
| **A. 成功報酬** | 配送事業者 | 再配達1件の削減 | 削減コスト300円の **1/3 = 100円/件** `[要検証]` | ◎ 効果と請求が直結。最初はこれ |
| **B. 設備SaaS** | マンション管理・設備事業者 | 宅配設備の稼働率向上・入退管理 | 1棟あたり月額 3,000〜10,000円 `[要検証]` | ○ 単価は低いが解約しにくい |
| **C. API従量** | EC・小売 | 配送成功率・CVR改善 | 1配送あたり 10〜30円 `[要検証]` | △ 効果の帰属が証明しづらい |

**生活者は無料**。生活者は「支払者」ではなく「受取成功率を上げる参加者」として扱う。

### 5.2 ユニットエコノミクス（粗い試算・`[要検証]`）

```
前提: 中堅配送事業者1社、担当エリアの年間取扱 3,000万個
      再配達率 8.3% → 再配達 249万件/年
      本サービス導入で再配達を 20% 削減 → 49.8万件/年の削減
      再配達1件の直接コスト 300円 → 削減額 1.49億円/年
      成功報酬 1/3 → 売上 4,980万円/年（1社）
```

この試算の生死を決めるのは次の3つだけである。

1. 再配達1件の**本当のコスト**（社内で誰がどう計上しているか）
2. 受取先を動的に変えられると**再配達が何%減るか**
3. 削減効果を**どう計測して合意するか**（計測できない改善には払われない）

→ これが[検証計画](./validation-plan.md)の中心になる。

### 5.3 市場規模（粗い積み上げ・`[要検証]`）

| レイヤー | 計算 | 規模 |
|---|---|---|
| TAM（再配達の社会的無駄） | 4億件 × 300円 | 約 **1,200億円/年** |
| SAM（本サービスで取りに行ける範囲） | TAM × 削減可能20% | 約 **240億円/年** |
| SOM（3年後に現実的に取れる範囲） | SAM × 10% | 約 **24億円/年** |
| 隣接（設備SaaS） | 分譲713万戸のうち集合住宅管理 × 月額 | 別途積み上げが必要 |

## 6. ガバナンス — どこまで自動化し、どこに人間を残すか

これはAIエージェントのガードレール設計とまったく同じ構造を持つ。
**全部自動化することが目的ではない。** リスクに応じて人間の介入点を設計する。

| 自律レベル | 挙動 | 適用 |
|---|---|---|
| L0 手動 | 受取方法の決定も受渡しも人間 | 現状の宅配 |
| L1 提案のみ | AIが提案、実行は毎回人間が承認 | 導入初期 |
| L2 低リスク自動 | 常温・低額のみ自動 | 日用品の定期便 |
| **L3 例外時のみ人間**（推奨） | 正常系は自律実行、例外だけエスカレーション | **既定値** |
| L4 屋内まで委譲 | 玄関解錠・屋内搬入まで委譲 | **採らない**（3.3節） |

実装としての判断点の例:

```
在庫確認            → 自動
少額商品の発注      → 自動
高額商品の発注      → 人間承認
公道の配送          → 自動
共用ロッカーへの格納 → 自動
受取先の動的変更    → 自動（ただしポリシー判定を通す）
本人確認が必要な交付 → 人間（本人）
自宅内へのアクセス   → 承認しない
```

## 7. 責任分界 — 何か起きたとき誰の責任か

自動化が進むほど、この設計が事業の生死を決める。技術ではなく契約・ルールの問題である。

| 区間 | 責任保持者 | 主なリスク |
|---|---|---|
| 発注 | 利用者／委任されたAIエージェント | 誤発注・過剰発注 |
| 出荷 | EC・小売事業者 | 誤品・欠品・破損 |
| 輸送 | 配送事業者（ロボット運行者） | 遅延・破損・事故 |
| 受渡し | 受取地点の運営者 | 盗難・認証失敗・温度逸脱 |
| 保管 | 利用者 | 受取後の紛失・品質劣化 |

### 7.1 「配送完了」と「受渡完了」を分ける

現行の置き配は、この2つが曖昧なまま「配送完了」で終わっている。だから盗難時に誰も責任を持てない。

本サービスでは **占有移転（CUSTODY_TRANSFER）イベントの成立をもって受渡完了**と定義し、
その瞬間の条件（誰が・どの認証で・どの温度で・どの証跡とともに）を署名付きで残す。

- 温度逸脱がどの区間で起きたかが分かる → 設備運営者の責任
- 認証を通さず開錠された記録があるか → 配送事業者の責任
- 受取後の紛失 → 利用者の責任

**責任分界は「記録の粒度」で決まる。** だから証跡設計が製品の中心にある。

### 7.2 AIの誤発注は誰の責任か

「AIが勝手に発注した」ケースの責任は、**委譲の記録があるかどうか**で決まる。
グラントと同じ形式で「発注権限の委譲」も記録しておく必要がある（現状デモでは `ordered_by: ai_agent(delegated)` として表現）。
ここは法務的な整理が必要な未解決論点（[open-questions](./open-questions.md) 参照）。

## 8. 例外設計 — ここが製品の本体

正常系（不足検知 → 発注 → 配送 → 受取 → 保管）の自動化は比較的考えやすい。
**価値が出るのは例外時の処理速度**である。

| 例外 | 自動でやること | 人間に戻すこと |
|---|---|---|
| ロッカー満杯 | 空きのある隣接Hubへ再ルート、旧グラント失効・再発行 | 候補提示と選択（L2以下） |
| 認証失敗（3回） | — | **必ず人間に戻す**。リトライで突破させない |
| 冷凍設備故障 | 温度逸脱を記録し配送中断 | 返送・返金の判断 |
| 通信障害 | グラントの期限切れで**権限が自動失効**（fail-safe） | 現地対応の手配 |
| 配送ロボットが襲われた | 全庫室を施錠維持・グラント即時失効・位置発信と通報 | 運行停止・通報・荷主通知 |
| 受取人が長期不在 | 保管期限前に冷蔵Hubへ移送、委任先への切替を提案 | 保管延長 or 返品 |

設計原則:

1. **権限は時間で切れる。** 通信が切れたら「開かない」のが正しい挙動
2. **認証失敗はリトライで突破させない。** 失敗回数は必ず人間に返す
3. **ロボットを制圧しても中身と住居権限が取れない構造にする**
4. **例外の大半は「時間切れ」。** 期限の設計が運用コストを決める

## 9. なぜ今か（Why now）

| 変化 | 内容 |
|---|---|
| 労働供給の崖 | 2030年度に輸送能力が約34%不足する試算。再配達の削減は「コスト削減」から「事業継続」の問題になった |
| 置き配の標準化 | 置き配が制度として前提化し、その副作用（盗難・プライバシー）が顕在化した |
| 法制度の整備 | 2023年4月の改正道路交通法で自動配送ロボットが「遠隔操作型小型車」として届出制で公道走行可能に（長さ120cm×幅70cm×高さ120cm以下、最高速度6km/h）。2025年2月には経産省WGが「より配送能力の高い自動配送ロボット」の社会実装を検討 |
| AIエージェントの実運用化 | 発注・決済までAIが実行する設計が現実的になった。**受取が相対的にボトルネックになった** |
| 世帯構造 | 単独世帯34.6%（2024年）→ 2050年に44.3%。「家に人がいない」が標準になる |

**AI時代に重要なのは、既存プロセスの一部をAIに置換することではなく、
AIが自律的に動く前提でプロセス自体を再設計すること。** これはIT運用（ServiceNow / Dynatrace的な領域）で
すでに起きていることで、同じ構造が物理世界に波及する。

```
IT運用:   認識 → 推論 → Action → ガードレール → 監督・承認
物流:     認識 → 判断 → 発注 → 移動 → アクセス → 受渡 → 保管
```

どちらも「誰が実行し・どこまで自律化し・誰が監督し・誰が責任を持つか」の設計問題である。

## 10. 競合・既存プレイヤーと差別化

| プレイヤー | やっていること | 本プロジェクトとの関係 |
|---|---|---|
| PUDO（Packcity Japan） | キャリア横断のオープンロッカー 約6,000カ所 | **競合ではなくノード**。Receiving Graphに載せる対象 |
| コンビニ受取（各社） | 店舗での受取 | 同上 |
| Amazon Hub / ロッカー | 自社完結の受取網 | 垂直統合の対抗軸。囲い込みの外側を束ねる |
| ヤマト・佐川・日本郵便のアプリ | 自社荷物の受取変更 | **キャリアごとに分断されている**点が機会 |
| 置き配バッグ（OKIPPAなど） | 玄関前の簡易保全 | 常温のみ。冷蔵冷凍と本人確認は解けない |
| 自動配送ロボット各社 | 走行・配送の自動化 | **相補**。ロボットが到着した後の権限と受渡しを担う |
| マンション宅配BOX | 常温・容量固定 | 満杯問題を再ルートで吸収する |

**差別化の核**: 各社が「自社の箱」を増やす競争をしている一方で、
**キャリアと設備を横断して受取権限を発行・失効できる層は誰も持っていない**。
ここはITの世界でいうIDaaS（Identity Provider）に相当するポジションで、
一度標準になると置き換えコストが高い。

## 11. リスクと対処

| リスク | 深刻度 | 対処 |
|---|---|---|
| 配送事業者が自社アプリで囲い込む | 高 | キャリア横断であること自体を価値にする。単独では実現できない「他社荷物も含めた受取集約」で入る |
| 効果測定に合意できず成功報酬が成立しない | 高 | 最初にA/B可能な測定設計を持ち込む。測れないなら固定フィーに切り替える |
| 権限の悪用・なりすまし | 高 | 最小スコープ・時限・失効可能・全イベント署名。屋内アクセスは扱わない |
| 位置情報のプライバシー | 中 | 位置は受取直前の限定時間のみ開示、受取完了で即失効（`ephemeral_location`） |
| 設備側のAPIが開いていない | 中 | Phase 0はキャリアの既存「受取場所変更」機能のオーケストレーションから始める |
| 法規制（薬機法・食品衛生法・宅配の約款） | 中 | 医薬品の第三者委任は**制度上できない**ものとしてポリシーに実装済み。法務確認が必要 |
| AIの誤発注責任の未整理 | 中 | 発注権限の委譲もグラント化して記録。法務整理は未完了 |

## 12. 90日ロードマップ

| 期間 | やること | 完了条件（Exit criteria） |
|---|---|---|
| Day 1–14 | プロトタイプを人に触ってもらい、利用意向と支払意思を集める（[デモ](../app/)の検証タブ） | 有効回答 30件以上。立場別の意向が分かる |
| Day 15–45 | 配送事業者・不動産事業者へのインタビュー5社 | 再配達1件の**社内コスト**の実数を2社以上から得る |
| Day 46–60 | 効果測定の設計（何をもって削減と見なすか）を1社と合意 | 測定方法の合意メモ1本 |
| Day 61–90 | 1エリア・1キャリアでのパイロット設計（既存ロッカー＋受取先変更のみ） | パイロット実施のLOIまたは意向確認 |

**撤退条件**: Day 45までに「再配達1件のコスト」の実数が誰からも出てこない場合、
課金根拠が存在しないということなので、事業の前提を組み替える。

## 13. 現時点での中心的な問い（4つ）

最終的に考えたいのは配送ロボットの実現方法ではなく、社会インフラの再設計である。

| # | 問い | 現在の答え（仮） |
|---|---|---|
| ① **Pain** | 設備投資してでも解消したいペインはどこにあり、誰が持っているのか | 生活者の「面倒」ではなく、配送事業者の再配達コスト。ただし実数は未確認 |
| ② **Process** | AI・ロボット前提で物流プロセスをどう再設計すべきか | 受取先を静的な住所から動的な「権限つき地点」に変える。Human-to-Human から Machine-to-Machine へ |
| ③ **Governance** | どこまで自律実行させ、どこに人間の承認を残すか | L3（例外時のみ人間）を既定。屋内アクセスは渡さない |
| ④ **Responsibility** | 複数のAI・ロボットが関与する場合、責任分界をどこに置くか | 占有移転イベントの成立点。粒度の細かい署名付き証跡で切る |
